# 已有模型导入与 GLB 布局

在“自有家具库 → 或导入已有模型”选择本机 GLB，核对类别、宽深高和正面方向，再确认保存。已有模型不需要识别或网格重建；没有实测尺寸时使用类别模板，并在卡片注明。无照片的家具卡片显示三维模型，来源说明保存在资产中。

应用的布局网络使用家具类别、确认尺寸和位置，不直接编码三角网格。生成流程保留 `assetUrl`、家具资产 ID、快照、尺寸和锁定姿态：搜索阶段对 GLB 使用保守矩形占地筛选，完整候选再用原模型做碰撞复核。相交检测批量计算三角形分离轴，修正旋转部件的坐标，限制变换网格与 BVH 缓存数量。

该策略可能漏掉能利用模型内部空隙的紧凑摆法。最终碰撞验收未放宽；规则、智能和单独模型路径会如实说明来源，单独模型可能找不到合格候选。

本机 2026-11-22 工程检查：三个包含 1、2、3 件真实 GLB 的房间，修复前均超过 25 秒未返回；修复后返回三个通过检查的候选。一次实际浏览器运行中，7 件家具含 3 件 GLB，约 4 秒完成生成，随后预览、应用、保存与重新读取通过。这是有限本机样例，不是所有房间的性能或质量保证；模型缺损和非实测尺寸仍须人工核对。

自动验证包含碰撞与空隙、锁定及元数据保留、导入发布、生成预览隔离、应用与保存。可运行：

```powershell
.\.venv\Scripts\python.exe -m pytest backend/tests -q
Set-Location frontend
npm run build
npm run test:e2e -- tests/glb-layout.spec.ts tests/furniture-model-import.spec.ts
```

浏览器回归使用独立临时数据库和端口，并关闭付费接口。单图/三视图重建的独立适配见 [InstantMesh 安装说明](../integrations/instantmesh/README.md)；已有 GLB 导入与布局不依赖该推理环境。

同步前在发布副本复跑：后端 538 项通过、4 项跳过，前端构建通过，6 项相关浏览器回归通过。兼容性复核覆盖已有 CUDA worker；草稿打开时先确认历史任务状态，避免已结束的任务刷新覆盖未保存编辑。图片重建质量未作为这些自动回归的验证结论。
