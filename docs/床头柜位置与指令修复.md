# 床头柜位置与指令修复

2026-10-20。本轮针对“带靠窗、靠墙要求生成后，床头柜仍落在床尾”和“床头柜放床头的右侧被拒绝”两项体验问题。

## 原因

上一版只在普通整屋生成中优先采用床与床头柜的组合模板。存在明确空间要求时，程序会使用另一条局部搜索路径；该路径只对窗边桌椅成组，仍单独搜索床头柜的位置。排序分数不能保证床头关系。

语言模型当时也未被授予床与床头柜之间的执行动作，因此拒绝该要求符合旧能力表；更换模型或扩充提示词本身不能让坐标执行器支持这一关系。

## 本轮修改

- 新增 `bedside` 关系：床头柜、对应床、床头左侧／右侧／任一侧，以及必须或尽量满足。
- 床头取渲染模型中枕头和床头板所在的局部 `-z` 端；左右按“站在床尾看向床头”定义，右侧为床局部 `+x`，与观察相机无关。
- 床头柜跟随对应床的最终位置和旋转，不再从整个房间随机选一个空位。带靠窗、靠墙要求和生成回退也要经过床头关系检查。
- 验收分别检查床侧间距、床头对齐偏差、侧别、占地和通路。几何不碰撞和床头关系满足分别显示，避免一个绿色提示代表所有条件合格。
- “床头柜放床头的右侧”等已完整识别的短句直接由本地执行器处理，无需付费语言接口；其他自然表达仍由语言模型转成已实现动作。未支持的复合要求整句反馈，不只执行其中一部分。

当前床头关系使用床侧间距不超过 0.35 米、床头对齐偏差不超过 0.30 米等可调整工程默认值，不能将其称为人体工学或建筑标准。柜体占地重叠仍由独立空间检查拒绝。

## 使用

可以输入“床头柜放床头的右侧”“把床头柜挪到床头左边”或“床头柜靠着床头”。多张床或多个同名床头柜需指定完整名称或 ID。已锁定的柜体不会被自动移动；要求不可能满足时需要明确解锁或调整条件。

如果此前右侧要求被拒绝，需要重新发送一次，让新关系进入“已识别的布局要求”。旧版本已经应用的摆法不会在刷新时被擅自重排。

## 验证与证据

测试覆盖旋转后的床、左右两侧、床头与床尾区分、多床目标、锁定与不可行情况，以及带靠窗／靠墙条件的六件家具场景。网页检查覆盖原句、已识别条件、候选独立位置换算、预览与应用。

`scripts/verify_bedside_regression.py` 重建截图中可见的房间尺寸、家具类别和要求，再独立用床的局部坐标检查床头柜，材料不是用户导出的精确场景。该脚本仅调用本地布局生成，不调用语言模型。最终运行数字和结果保存在 `docs/bedside_checks.json` 与 `artifacts/interaction_checks/bedside_after.json`。

这轮验证不宣称已解决所有自然语言关系、软装审美或精细柜门开启问题，也没有把模拟模型响应称为真实接口准确率。
