## 当前配置与开关

开发验证期间已完成三次真实接口调用，密钥不随仓库分发。新环境需要自行配置；不要把已填写的文件复制到公开包。

在仓库根目录创建 `runtime` 文件夹，将 `language.config.example.json` 复制为 `runtime/language.local.json`，再打开该私有文件填写自己的 DeepSeek API 密钥。已有配置不覆盖。不要把密钥放到网页代码、聊天记录或公开源码中。示例：

```json
{
  "enabled": true,
  "provider": "chatcompletions",
  "url": "https://api.deepseek.com",
  "model": "deepseek-flash",
  "apiKey": "在本机填写",
  "responseFormat": "json_object"
}
```

也可将项目根目录 `.env.language.example` 复制为 `.env.language`，填写并取消注释 DeepSeek 配置（已有文件不要覆盖）。配置优先级为：后端进程环境变量 > 项目根目录 `.env.language` > 私有 JSON > 默认关闭。两个文件均在健康检查和每次指令时重新读取，保存后刷新网页即可，无需手动导入环境变量，与启动工作目录无关。修改进程环境变量则需要重启后端。

JSON 的 `enabled:false` 仅在没有更高优先级 provider 时生效；若要强制所有配置离线，在后端进程环境中设置 `ROOMWISE_LANGUAGE_PROVIDER=disabled`。空密钥或无效文件会关闭语言调用并给出安全提示；不会将密钥写入健康检查响应。`.env.language` 的语法和可选路径覆盖见 `.env.language.example`。`/api/health` 中 `language.enabled=true` 表示配置通过本地检查，不代表远端接口已经连通；健康检查不会请求付费接口。

模型名称和接口按核查当日 [DeepSeek 官方接入文档](https://api-docs.deepseek.com/) 配置；账户能否使用及收费以控制台为准。需要 API 账户和额度，网页聊天会员不能自动代替 API 密钥。

启用后，每次发送文字指令可能计费；刷新、预览、拖动和普通布局生成不需要调用语言接口。关闭接口不影响这些本地功能。自动测试必须使用 `ROOMWISE_LANGUAGE_PROVIDER=disabled` 的独立后端8766，以及代理该端口的 `frontend/vite.integration.config.ts`，详见 [README](../README.md)。不要对已配置密钥的8765运行批量指令回归。

## 它怎样工作

语言模型收到当前文字要求、选中家具、家具 ID/名称/尺寸/位置/锁定信息及门窗几何，输出 JSON 意图。没有上传照片、家具网格、资源地址、参考图或本机文件路径。响应须通过格式、真实对象、动作能力、单位、锁定和整句原子检查后，才能交给原有执行器。

使用 DeepSeek 的 `json_object` 格式，并在提示中给出 schema 和例子；这不是服务端强制遵守 schema 的保证，所以程序仍做本地校验。关闭 thinking、最多 2048 个输出 token；每次指令最多一次请求，不自动重试。空响应、超时或格式错误返回“未执行”，不假装成功。依据：[DeepSeek JSON 输出](https://api-docs.deepseek.com/guides/json_mode/)。

支持的动作目前为床头柜位于指定床的床头左／右侧、靠墙、靠窗、面朝窗户、尽量少移动、保留、锁定、明确解锁、相对移动、相对旋转、仅调整指定家具、生成及撤销。语言模型可扩展这些动作的表达方式，不会凭空增加颜色材质、风格换装、任意家具关系和真实商品选配能力。

“保留”只保护家具身份，“保持原位”还要求位置与朝向不变。新增的锁定检查遇到模型漏掉这一要求时，会拒绝整句并提示重述，不能把遗漏默认为成功。“只调整书桌，向右挪20厘米”属于明确编辑；完成位移后不会再自动生成另一套布局。若编辑造成碰撞，系统报告冲突，不声称布局可用。

普通规则/混合布局已加入床与床头柜、桌椅、柜体靠墙等成组候选；这是本地规则模板，来源标注不算网络推理。明确的靠墙、靠窗等局部要求走专用约束搜索，优先保留未提及物品；确需移动未锁定的阻挡物时说明变化，无法满足时说明原因。其目的是改善候选结构，尚未证明符合所有家庭的审美。

## 三次真实调用说明了什么

证据为 `artifacts/interaction_checks/deepseek_live_commands.json`，保留修复前的原始响应，未覆盖成成功记录：

| 指令 | 实际观察 | 后续处理 |
| --- | --- | --- |
| 只把书架贴墙边，其他家具别动 | 正确给出书架对象、限定范围和靠墙动作 | 不代表生成的最终房间已通过使用与审美评价 |
| 书桌靠窗、办公椅面向窗外、衣柜保持原位 | 前两项识别正确，衣柜被误作 `keep`，遗漏应有的 `lock` | 增加位置锁定检查，漏锁时整句拒绝 |
| 只调整书桌，把它朝右挪20厘米 | 识别出相对移动，但旧执行分流错误返回再次生成 | 已修正为编辑，不再自动二次重排 |

上述三次交互修复完成时没有进行第四次真实调用；2026-10-24 新增的单次配置链路验证见本文开头，不作为这三条原始指令的重测。现有证据只能说明链路可用并暴露了问题，不能声称“3/3理解正确”或“绝大多数指令可用”；本地模拟与回归也不能替代真实模型验证。

## 两类效果要分别验证

- **理解效果**：输入相同动作的不同说法，对象、否定、单位、锁定与执行范围是否正确。成功输出 JSON 只代表格式合格。
- **布局效果**：要求是否全部满足，其他家具是否被无谓移动，桌椅是否成组，边界、碰撞和通路是否通过。没有碰撞不等于舒适或美观。

54 条自制语义用例与完整场景在 `data/interaction_benchmark_v1.jsonl`，其中18条 `planned` 是升级前的能力快照，部分靠墙能力现已补齐；版本更新前不能用旧标注当作当前成功率。开发与公开验收材料都由开发者编写、可读取，不称为独立盲测。更广泛的真实指令覆盖率和设计偏好，要收集新的表达并实际评测后才能报告。

后续升级顺序见 [智能交互与布局升级方案](智能交互与布局升级方案.md)：继续扩展可执行关系和成组模板，优化多个候选，再用人工偏好验证。现有坐标去噪模型暂作为可选候选来源，不能冒充通用中文或软装设计模型。
