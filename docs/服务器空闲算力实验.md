# 上一台服务器的空闲算力实验准备记录

更新日期：2026-10-16。

本文保留上一台共享采集服务器的准备说明。**现在已经有独立的新服务器，实际推进步骤见 [新服务器推进指南](新服务器推进指南.md)**；不要把旧机器的采集完成条件、环境路径或启动参数带到新机器上。

## 当时的约束

上一台 T4 服务器正在运行原有的采集程序。用户首先要求保证采集不受影响，随后明确要求“先不要排队了，做些准备工作就好”。因此当时只做了只读检查和本地准备，没有上传运行训练、创建等待队列、定时任务或采集结束后自动启动实验的任务。

查看 CPU、内存、磁盘和进程状态不会停止采集，但安装依赖、加载 GPU 模型或开始训练可能与采集争用资源。GPU 显存占用少，也不能证明计算资源空闲。因此当时没有利用采集中的空隙强行并行训练。

## 已准备的内容

- 家具布局模型的 CPU/GPU 训练、验证和评估代码。
- 按住宅划分的预处理卧室数据和已有参考权重。
- 明确列入文件的私人传输包 `release/Roomwise_server_experiments.zip`，不包含 SSH 密钥、原有采集日志、用户媒体或完整开发环境。
- 手动实验脚本 `backend/scripts/run_idle_experiments.py`：检查本机是否还有 `profile_full.py`，CUDA 实验还检查 GPU 是否已有计算进程；条件不满足时直接拒绝，不自动等待。

旧的 `prepare_server_environment.py` 原本为旧机器设计，需要核对采集完成记录并只读复用旧环境中的一部分依赖。它不是独立新服务器的安装方式。新服务器应使用 `prepare_new_server.py` 建立全新的项目环境，无需旧采集的完成标记或环境。

## 实验目标与结果边界

准备的布局实验比较两种干净样本比例、两个随机种子，以验证集选择是否存在比参考权重更好的候选，最后用测试集报告选中结果。检查位置与角度误差、无扰动输入漂移、越界、重叠以及锁定家具是否改变。

这些是模拟卧室布局实验，不是完整房屋重建，也不能直接证明真实用户更喜欢方案。候选不会自动覆盖应用模型；下载结果后还需要在本地进行完整应用对照。

本地测试通过只代表代码准备完成，不代表旧服务器或新服务器已经完成 GPU 训练。实际上传、安装、试运行与正式实验状态应分别记录，避免把“已准备”写成“已运行”。
