## 3. 上传并校验实验包（本次已完成）

本地文件是 `app/release/Roomwise_server_experiments.zip`，同时提供同名的 `.manifest.json`。这是约 4 MB 的私人实验包，包含训练代码、预处理数值数据和参考权重；不包含前端、视频、原始大型数据包或虚拟环境。本次已传入 `/home/your-user/roomwise-project`。数据盘根目录不允许 `ubuntu` 创建目录，因此本次选用自己的主目录。

在服务器执行以下命令，先核对大小和 SHA256，再检查 ZIP：

```bash
cd /home/your-user/roomwise-project
python3 - <<'PY'
import hashlib
import json
from pathlib import Path

package = Path('Roomwise_server_experiments.zip')
manifest = json.loads(Path('Roomwise_server_experiments.manifest.json').read_text(encoding='utf-8'))
assert package.stat().st_size == manifest['bytes'], '文件大小不符，请重新传输'
assert hashlib.sha256(package.read_bytes()).hexdigest() == manifest['sha256'], 'SHA256 不符，请重新传输'
print('实验包校验通过')
PY
python3 -m zipfile -t Roomwise_server_experiments.zip
```

检查通过后解压到自己的实验目录。该目录应没有旧版实验包；如已有同名目录，改用另一个新的目录，避免覆盖文件。

```bash

cd /home/your-user/roomwise-project/roomwise-experiments

```

随包 `verify_package.py` 会逐个检查内部文件的哈希。外部清单随每次打包更新，本文不固定写入会过期的 ZIP 哈希。这些 3D-FRONT/LEGO-Net 衍生输入与权重用于团队授权研究，不能把这个私人 ZIP 当成开源代码包发布。

## 4. 新建独立环境（本次已完成）

下面的环境脚本适用于 Linux、Python 3.10–3.12。它使用官方 PyTorch 2.4.1 CUDA 12.1 安装源；是否与新服务器驱动匹配，仍以实际检查和短试运行为准。不要复制本机 Windows `.venv`，也不要复用上一台服务器的采集环境。

先查看安装计划，**这条命令不安装包、不运行训练**：

```bash
python3 app/backend/scripts/prepare_new_server.py --device cuda --env-dir /home/your-user/roomwise-project/experiment-venv
```

确认系统、Python、显卡和磁盘符合要求后，手动创建新环境。本次实际已执行并完成下面的命令；不要重复执行：

```bash
nice -n 19 ionice -c 3 taskset -c 30,31 python3 /home/your-user/roomwise-project/roomwise-experiments/app/backend/scripts/prepare_new_server.py --device cuda --env-dir /home/your-user/roomwise-project/experiment-venv --create
```

该命令联网下载依赖并做环境检查，不启动训练。本次实际安装 NumPy 1.26.4、Shapely 2.0.7、PyTorch `2.4.1+cu121`，CUDA 小矩阵计算和参考模型 CPU 前向检查均通过。使用全新的环境目录；已有环境不会被覆盖。若重复做新实验，需要选择新的环境路径或先核查已有环境，不要覆盖其他项目环境。

`nice -n 19` 降低 CPU 调度优先级，`ionice -c 3` 请求空闲 I/O 优先级，`taskset -c 30,31` 将进程及其子进程约束在两个逻辑 CPU 上。这些措施限制资源使用，不能硬隔离共享 GPU、磁盘、网络或缓存，不能保证其他实验重新开始后完全不受影响。

开始安装和实验前，先确认本机其他实验已结束，或用户已明确安排可用资源。新机器若已有其他 GPU 任务，先保留其运行，稍后手动执行实验。本项目没有后台等待或自动启动机制。独立环境只能避免依赖互相覆盖，不能隔离 CPU、GPU、磁盘和网络争用。

## 6. 做四组有目的的对照实验

短流程通过后，手动运行正式实验。本次四组已完成，阶段总耗时约 99.31 秒：

```bash
nice -n 19 ionice -c 3 taskset -c 30,31 /home/your-user/roomwise-project/experiment-venv/bin/python app/backend/scripts/run_idle_experiments.py --device cuda --threads 2 --batch-size 128 --epochs 40 --max-seconds-per-run 180 --seeds 20261016 20261017 --output-dir app/results/cuda-study-20261016
```

它从参考权重继续训练，比较两种干净数据比例（12%、40%）和两个随机种子，共四个候选。单组最多 40 轮，训练时间限制为 180 秒，脚本在批次和轮次之间检查时间；验证、评估与保存还会额外耗时，因此这不是整个命令的硬性超时。训练也可能提前停止；实际轮数、时间和环境以结果记录为准。

候选只按验证集比较：除了位置和角度误差，还检查干净布局漂移、越界、重叠和锁定家具变化。只有符合这些比较条件且分数更好，才选择候选；否则保留参考模型。最终仅对选中的模型报告测试集指标。脚本会生成 `experiment_summary.json`、各组日志、权重、验证指标、最终测试指标及 `.results.zip`。

脚本会拒绝与已知的 `profile_full.py`、`stage.py` 或 FFmpeg 进程并行，也会在 GPU 已有计算任务时拒绝启动，不会等待或排队。这些检查不能识别任意名称的其他实验；启动前仍需确认整台机器的任务安排。生成的候选不会自动覆盖本地应用权重。

训练内部按单步验证选择保存轮次，再按三步验证比较保存后的候选，不能据此声称找到了三步推理的最佳轮次。测试划分在先前项目实验中已经报告过，本轮复用它作为固定回归基准，不把它称作全新的未接触测试集。

本次结果已下载至本地 `app/artifacts/server_runs/20261016`，完整证据 ZIP 和内部文件校验通过。见 [完整结果包](../artifacts/server_runs/20261016/Roomwise_T4_evidence_20261016.zip) 和 [实际运行记录](服务器实际运行记录_20261016.md)。服务器退租前应保存需要的日志和模型；本轮已完成本地备份。

四组各追加训练 12 轮，但均未刷新验证最优轮次；最终保存参数与原参考模型相同，因此没有替换应用权重。应用对照的 12 个自制场景中，规则与模型结合规则均成功处理 10 个普通场景并拒绝 2 个预设失败场景；结合模型没有显示成功数优势，而且仍依赖几何修复。该结果仅用于本轮工程验证，不代表真实房屋总体效果。

结束后再次检查，GPU 为 0 MiB、0% 且无计算进程，本项目训练与评估均已退出；系统盘约剩 26G，数据盘约剩 79G。没有自动等待下一轮，可按原有方式恢复其他实验，保留本项目目录即可。下一次重新运行本项目仍需先核查同机任务安排。

比较结果时需要区分两件事：

- 模型在模拟扰动数据上是否减少了位置误差、角度误差和无谓移动。
- 加入模型的完整应用，是否在相同场景和预算下优于原来的规则布局器。

第一项变好不代表第二项自动变好。原模型仍需要几何修复，不能仅凭训练损失下降就宣称“生成的方案更合理”。候选通过验证后，再在本地应用做规则布局与模型结合布局的相同场景对照，记录成功率、耗时、越界/重叠、家具尺寸及锁定状态是否保持，以及结果是否依赖几何修复。

最后根据证据决定是否接入候选模型；未证明改进时继续使用参考模型。真实搬家效果、风格偏好和三维重建能力还需要各自的数据与实验，本次布局对照不能替代这些验证。
