# 自有家具图片导入：使用、配置与验证

## 1. 能做什么，以及不能做什么

功能位于布局之前的家具资产输入层：图片 → 多视图联合识别 → 草稿核对 → 参数化近似三维 → 家具库 → 房间实例。用户无需先填写类别。类别、尺寸、方向和结构均须人工确认，不因模型自信而跳过确认。

- 一件家具支持 1—3 张 JPEG、PNG、WebP，每张至多 10 MB、4000 万像素；可输入实拍、渲染、工程图和拼接三视图。
- 类别限于现有 20 类；未知类别保留空值和细分类别，用户明确选择近似类别后才可发布。
- 普通照片或无标尺三视图不能恢复可靠绝对尺寸。图纸标注读取、视觉估计、用户填写分别记录，单位统一为米。估计值不是实测值。
- 生成的是参数化模型，不是精细三维重建；颜色、材质与风格仅为外观判断。不可见结构使用模板默认值，模型不执行建模代码。
- 对不同物品混传、多目标、视图冲突和待裁剪结果禁止发布，应裁剪、拆图或补拍后重新上传。
- JSON 场景保存资产快照和本地资源地址，不把照片、GLB 文件打包。复制到另一台电脑时，仅复制 JSON 不能迁移完整资产。

## 2. 配置视觉模型

代码默认关闭云端识别，现有 DeepSeek 文字指令配置不会启用图片识别。关闭时上传仍会保存本地草稿，可手工补全；没有偷偷替代的识别结果或默认实测尺寸。

按用户提供的配置，使用 **OpenAI 兼容 Responses API（Application Programming Interface，应用程序接口）**，通过第三方网关将多图一次提交，使用严格 JSON Schema（字段结构约束）输出和本地 Pydantic 校验。后端锁定根地址 `https://api.tokenlab.pro`、型号 `gpt-6-sol` 和推理强度 `high`；不自动切换地址、模型或降低推理强度。

**`api.tokenlab.pro` 不是 OpenAI 官方域名。** 配置段名称 `OpenAI` 和 `requires_openai_auth=true` 不改变图片实际接收方。请提供该网关认可且有额度的密钥；代码使用 `Authorization: Bearer …`，不读取 Codex 登录凭据、配置文件或 ChatGPT 会话。官方模型文档确认 `gpt-6-sol` 支持图像输入、结构化输出和 `high` 推理，但不能证明网关提供相同能力或验证其上游模型身份；必须做真实烟雾验证，不要把本地“已启用”状态当作可调用证明。

给出的配置是 Codex TOML（Tom's Obvious, Minimal Language）格式，应用不自动导入。映射规则：`model_provider=OpenAI` → `ROOMWISE_VISION_PROVIDER=openai`；`model` → `ROOMWISE_VISION_MODEL`；`model_reasoning_effort=high` → 请求字段 `reasoning.effort=high`；`base_url` → `ROOMWISE_VISION_BASE_URL`；`wire_api=responses` → 固定 Responses 协议。`model_catalog_url=https://api.tokenlab.pro/v1/models` 仅用于模型发现，本功能不调用它，也不据此给推理地址补 `/v1`。

按给定根地址，推理请求固定为 `POST https://api.tokenlab.pro/responses`。若网关实际要求 `/v1/responses`，应先核对供应商配置再明确修改，不自动尝试备用路径或重复付费调用。高推理模式使用 15 秒连接超时、180 秒读写超时及 8192 输出 token 上限；输出截断时不采用部分结果。

应用现在自动读取 `app/.env.vision`，不依赖启动工作目录，不把文件内容写入全局环境；修改后重新打开家具库即可读取新状态。文件仅接受 `ROOMWISE_VISION_*` 白名单变量，支持 UTF-8 BOM、引号与注释；格式错误时关闭外发且不回显密钥。启动终端已有的环境变量优先于文件，尤其注意 `ROOMWISE_VISION_PROVIDER=disabled` 的覆盖。`.env.vision.example` 仅为模板，不会被自动载入。

推荐把 `.env.vision.example` 复制为 `.env.vision`，将 provider 改为 `openai` 并填入密钥。也可在启动后端的 PowerShell 窗口设置：

```powershell
Set-Location D:\code\pythonProjects\roomwise\app
$env:ROOMWISE_VISION_PROVIDER = 'openai'
$env:ROOMWISE_VISION_MODEL = 'gpt-6-sol'
$env:ROOMWISE_VISION_BASE_URL = 'https://api.tokenlab.pro'
$env:ROOMWISE_VISION_REASONING_EFFORT = 'high'
$env:ROOMWISE_VISION_API_KEY = [System.Net.NetworkCredential]::new('', (Read-Host '视觉服务密钥' -AsSecureString)).Password
conda run --no-capture-output -n roomwise python -m uvicorn roomwise.main:app --app-dir backend --host 127.0.0.1 --port 8765
```

若原服务仍在运行，先在其终端正常停止，再使用同一端口启动；不要盲目终止不明进程。环境变量只对该窗口及子进程生效。不要在聊天、截图、源码或前端中填写密钥。

另开 PowerShell，前端使用 nvm 管理的现有 Node.js：

```powershell
Set-Location D:\code\pythonProjects\roomwise\app\frontend
npm run build
```

打开本地应用的 `http://127.0.0.1:8765`，点击左侧“家具”页顶部的“从图片生成家具”，或右上角“自有家具库”。服务状态也可通过 `GET /api/furniture/status` 检查；该接口不返回密钥或完整服务地址。构建网页与后端采用同源部署。

如果默认端口是另一个项目，不要打开该项目的前端，也不要终止其进程。可在 `app` 目录执行 `./start.ps1 -Port 8768`，再访问 `http://127.0.0.1:8768`；启动脚本优先复用现有名为 `roomwise` 的 Miniconda 环境，支持用 `ROOMWISE_PYTHON` 指定解释器。健康接口的 `application=roomwise` 用于避免误把其他服务当作本应用。

### 椅子三视图示例

从图片生成家具 → 选择文件，在文件对话框地址栏粘贴 `D:\code\pythonProjects\roomwise\data\photos\chair`，多选 `front_view.jpg`、`side_view.jpg`、`top_view.jpg`。可先框选椅子以去掉人物和其他家具；勾选云端发送与计费同意后提交。识别完成后核对类别、尺寸、方向、颜色及扶手等结构，预览是参数化近似而不是实物重建。没有标尺的照片只提供估计尺寸，发布前应实测或明确接受误差。核对五项后点击“确认并保存到家具库”，再“加入当前房间”。关闭窗口不会丢失识别草稿；重新进入家具库可在下方“待确认草稿”打开。

官方协议与模型能力参考：[GPT-6 Sol](https://developers.openai.com/api/docs/models/gpt-6-sol)、[多图输入](https://developers.openai.com/api/docs/guides/images-vision)、[结构化输出](https://developers.openai.com/api/docs/guides/structured-outputs)。这些文档不为第三方网关的兼容性作保证。所有字段均为必需键，无法判断的可空字段输出 null；严格结构不保证识别正确，最终仍由本地协议和人工核对约束。

## 3. 日常操作

1. 选择同一家具的 1—3 张图片。尽量完整拍到边缘，避免强遮挡；建议正面、侧面、背面或俯视，俯视不是必选。工程图尽量保留单位与尺寸线。
2. 背景有其他家具时，在图片上拖动框选，点击“使用框选区域”。裁剪在浏览器本地执行，尚未发送服务商。拼接三视图可保留整图；字太小请拆成独立图片。
3. 阅读图片外发和计费提示，勾选同意后点击“上传并识别家具”。后端校正方向、移除元数据，重编码保存原尺寸副本；仅将最长边不超过 2048 像素的缩放副本发送模型。
4. 查看视角、识别依据和不确定项。对比模型原值与当前值，核对名称、类别、宽深高、外观、结构和规范方向。床头为局部 `-z`，其他家具使用面为 `+z`。
5. 实时查看近似三维。未知结构使用模板默认值；尺寸缺失时不显示假装精确的预览。外观材质不代表实物成分认证。
6. 勾选全部五项核对，点击“确认并保存到家具库”。系统导出 GLB，经现有资产校验后发布；失败时草稿保留，可重试。
7. 在家具卡片点击“加入当前房间”。初始放在房间中央，可能与已有家具重叠；请移动后检查空间警告。每次加入都会创建独立实例，可撤销、旋转、锁定和参与布局。

房间实例使用自己的唯一标识，拾取模型时只使用房间实例根节点，而不采用模型文件中携带的旧标识。早期导出含 `furniture-preview` 标识的模型也可直接选中和拖动，不需要删除家具、重建模型或再次识别。新导出的模型不保存实例标识。同一家具可在不同方案重复加入，移动、旋转和锁定互不影响；保存或 JSON 导入后仍按实例操作。更新网页后若仍无法操作，请先保存当前方案，再强制刷新页面加载新代码。

“保存草稿”不会发布。关闭窗口不会取消已提交任务，下次打开可以从“待确认草稿”继续。未保存的本地修改关闭前会提醒。云端识别失败可手工补全，填写的尺寸会记录为 `user`，不会伪装成模型识别或图纸读取。

修改已发布家具会创建修订草稿，重新核对后发布新版本；旧场景继续使用原快照，修改库不会偷偷更改房间里的尺寸、模型或位置。

## 4. 故障、存储与隐私

| 状态 | 处理 |
| --- | --- |
| 服务关闭 / 配置缺失 | 不发送图片，保留草稿；可手工填写，或配置后明确同意重试 |
| 网络超时 / 限流 / 服务失败 | 不自动重试，避免重复费用；原图和草稿保留 |
| 返回字段非法 / 尺寸来源错误 | 不采用不合规结果；保留草稿，补图或手工填写 |
| 多个目标 / 不是同一物品 / 视图冲突 | 禁止直接发布，裁剪、更换图片后新建识别 |
| 图纸单位不明 / 尺寸缺失 | 留空，实测或补充清晰尺寸图后再确认 |
| GLB 导出或上传失败 | 留在草稿，重试发布；不要假称已经生成资产 |
| 草稿 / 资产版本冲突 | 重新打开当前版本，避免覆盖其他修订 |
| 进程异常退出 | 下次打开时将未完成任务标为中断；不自动重发付费调用 |

SQLite 新增家具草稿、任务、资产和发布去重表，与原场景表并存。上传位于 `runtime/uploads/furniture`，GLB 位于 `runtime/uploads/assets`。已发布资产引用的图片不会因草稿关闭被删除。当前只支持单后端工作进程，不要设置多个 Uvicorn workers。

仅模型处理用图片发送第三方网关 `api.tokenlab.pro`，不是直接发往 OpenAI 官方；房间全量、文字指令历史、本地路径、EXIF、模型文件不外发。请求设置 `store=false`，但不能保证网关遵守该字段，也不代表云端零保留或本地处理；提交前应了解第三方的数据处理政策和上游转发情况，不可直接套用 OpenAI 官方隐私承诺。移除元数据不等于图片匿名化，画面中的人脸、住址、票据等仍需在提交前裁剪。已有 DeepSeek 文字服务继续使用原白名单，不接收新增照片和家具档案。日志不保存图片编码或密钥。该程序仍是绑定本机的单用户原型，不应直接暴露公网，也未实现多用户授权与对象存储。

## 5. 先做真实识别验证，再宣称模型可用

仓库提供实测工具，但**不包含 30 组获得授权的真实家具图片，也不包含真实云端准确率报告**。模拟测试、生成的小图片和参数模型测试只验证工程链路，不能代替真实识别实验。

下面的初始化命令创建 30 组待填写定义，不创建真实图片或虚构实验结果。所有数据留在 D 盘：

```powershell
Set-Location D:\code\pythonProjects\roomwise\app
New-Item -ItemType Directory -Path runtime\furniture_validation -Force | Out-Null
conda run --no-capture-output -n roomwise python backend\scripts\evaluate_furniture_vision.py --init-manifest runtime\furniture_validation\manifest.json
```

填写每个样本的 `images`（相对 manifest 的路径）、`rightsConfirmed: true`、真值 `truth` 和风险说明。包含床、桌、椅、沙发、柜、架、地毯，单图、多视图、拼接图、尺寸图及遮挡、多物品、不一致视图。未知真值保留 `null`，不要用类别默认尺寸当真值。

先预检查，然后仅对 3 组做付费烟雾验证；命令需要同一窗口中的视觉服务配置：

```powershell
conda run --no-capture-output -n roomwise python backend\scripts\evaluate_furniture_vision.py --manifest runtime\furniture_validation\manifest.json --limit 3
conda run --no-capture-output -n roomwise python backend\scripts\evaluate_furniture_vision.py --manifest runtime\furniture_validation\manifest.json --limit 3 --allow-paid --confirm-image-rights --output runtime\furniture_validation\smoke.jsonl
```

只有多图接口、字段校验、未知值与失败提示都通过后，才去掉 `--limit 3` 跑全量 30 组，使用新的输出文件名。工具拒绝覆盖已有结果，记录脱敏结果、用量与耗时、类别/结构检查、风险拦截情况，并将图纸尺寸读取和照片尺寸估计的误差分开统计。费用以服务商账单为准；视觉识别自身不能证明厘米级测量准确性。

## 6. 工程回归（不付费）

后端测试默认强制关闭文字与视觉云端服务。可使用独立本地运行目录，避免污染日常方案：

```powershell
Set-Location D:\code\pythonProjects\roomwise\app
$env:PYTHONPATH = "$PWD\backend"
$env:ROOMWISE_LANGUAGE_PROVIDER = 'disabled'
$env:ROOMWISE_VISION_PROVIDER = 'disabled'
$env:ROOMWISE_RUNTIME_DIR = "$PWD\runtime\furniture_regression"
$testTemp = Join-Path (Split-Path $PWD -Parent) ('roomwise-tests-' + [guid]::NewGuid().ToString('N'))
conda run -n roomwise python -m pytest backend\tests --basetemp="$testTemp"
```

浏览器测试需要单独启动后端 `8766`（上述两个 provider 都保持 disabled）、Vite 集成代理，以及现有 Microsoft Edge。若 `5173` 被日常开发占用，可用 `5174`：

```powershell
# 窗口一，app 目录
$env:ROOMWISE_RUNTIME_DIR = "$PWD\runtime\furniture_browser"
$env:ROOMWISE_LANGUAGE_PROVIDER = 'disabled'
$env:ROOMWISE_VISION_PROVIDER = 'disabled'
conda run --no-capture-output -n roomwise python -m uvicorn roomwise.main:app --app-dir backend --host 127.0.0.1 --port 8766

# 窗口二，frontend 目录
npm run dev -- --config vite.integration.config.ts --port 5174

# 窗口三，frontend 目录
$env:ROOMWISE_E2E_BASE_URL = 'http://127.0.0.1:5174'
npx playwright test tests/furniture.spec.ts
npm run build
```

`ROOMWISE_RUNTIME_DIR` 同时隔离场景、家具和视频上传数据；日常启动时不设置即可使用原 `runtime`。不要把生产 `8765` 用作自动化付费模型测试目标。
