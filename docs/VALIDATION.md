- 规则搜索、实际训练模型重排、模型＋规则修复，候选必须独立检查才接受；初始化与修复来源在结果中记录。
- Three.js程序化独立家具；拖动、参数调整、旋转、锁定、撤销、SQLite版本保存、JSON导入导出、GLB/内嵌GLTF与图片绑定。
- 有限中文命令离线解析；歧义、否定、既有锁定冲突原子拒绝，不伪装为任意语义理解。

## 模型实验

训练144轮、5184步，模型73,604参数；独立测试682个房间、498户，与训练/验证住宅无交叉。给定位置标准差0.45米和角度标准差30°的人工扰动时，输入位置误差0.564米，模型三步0.229米，简单截断/角度规则0.425米。原始模型越界率36.96%，对干净布局仍产生约0.134米位置漂移。**它只是受控布局恢复实验，不能说明新房任意家具组合一定合理或比专业设计好。**

另有12个自行构造应用案例（10常规、2明确冲突），规则与模型＋修复都通过10个常规且拒绝2个冲突，身份/尺寸/锁定校验无违规。这些模型提案原始接受数为0，成功方案依赖几何修复；没有得出混合模式成功率优于规则。条件和逐例JSON见artifacts/experiments/app_metrics.json。实际模型数字见docs/TRAINING.md和heldout_metrics.json。

## 已知限制

1. 单个卧室/常见家具为主；预训练数据床、柜、床头柜多，书桌和罕见组合样本少。
2. 模型不生成精细三维网格，不决定市场SKU或真实购物价格；新增建议采用明确规则。
3. 生成最多32件家具，有搜索时间/次数上限。超时或无候选只表示未找到，不证明数学无解。
4. 通路采用网格和0.30米身体直径近似；门内矩形净空不精确模拟门扇，桌椅例外和地毯不是精细碰撞保证。
5. 文件与场景保存是本机用途；源训练数组/权重公开前要确认数据授权，不默认随源码分发。
